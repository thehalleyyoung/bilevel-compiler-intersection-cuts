# BiCut

BiCut turns bilevel linear programs with an integer leader into single-level
mixed-integer programs and checks every answer it returns.

- For a **continuous (LP) follower** it builds the big-M KKT reformulation
  with both complementarity families (constraint slacks and variable reduced
  costs) and solves it with HiGHS. Every point it returns is follower-optimal
  for any value of M; a too-small M can only make the MILP infeasible or its
  optimum worse, and the evaluation measures how often that happens.
- For an **integer follower** it combines the KKT model of the follower's LP
  relaxation, whose answers are checked with one follower MIP, with an exact
  loop over leader decisions bounded by the high-point relaxation (HPR). The
  loop proves optimality when the HPR bound meets the incumbent.
- A Rust workspace provides typed problem data structures, MPS/LP readers and
  writers, reformulation passes as library code, and a `bicut` CLI that reads
  a bilevel problem in TOML and writes its high-point relaxation.

The accompanying paper is [`tool_paper.tex`](tool_paper.tex)
([PDF](tool_paper.pdf)).

## Results

All numbers below come from the result files committed under `benchmarks/`
and are regenerated by the commands in [Reproducing](#reproducing).

### LP follower, 122 generated instances (`benchmarks/kkt_eval_output/kkt_eval.json`)

Four generated families with integer leader and LP follower
(`benchmarks/generators.py`). KKT model with M = 1000, HiGHS 1.15.1,
60 s limit. "Checked" means the returned (x, y) satisfies all constraints and
c^T y <= phi(x) for the follower LP value phi(x). "Exact" compares with the
optimum found by enumerating every leader vector, done where there are at most
4096 of them.

| Family | Instances | Solved to optimality | Checked bilevel feasible | Enumerated | KKT = exact |
|---|---:|---:|---:|---:|---:|
| Knapsack-type | 72 | 72 | 72 | 18 | 18 |
| Dense random | 28 | 25 | 25 | 4 | 4 |
| Pairwise coupling | 12 | 12 | 12 | 6 | 6 |
| Target defence | 10 | 10 | 10 | 6 | 6 |
| **Total** | **122** | **119** | **119** | **34** | **34** |

Of the three dense instances not solved at M = 1000, one is reported
infeasible for every M tested and two stop at the time limit with incumbents
that pass the check.

Sensitivity to M, on the 117 instances with a reference optimum (the
enumerated optimum, or the checked M = 10^4 optimum):

| M | Correct optimum | Reported infeasible | Feasible but suboptimal | Follower-suboptimal answer | Time limit |
|---:|---:|---:|---:|---:|---:|
| 1, 2, 5 | 0 | 117 | 0 | 0 | 0 |
| 10 | 40 | 70 | 7 | 0 | 0 |
| 50 | 115 | 1 | 0 | 0 | 1 |
| 100 | 116 | 0 | 0 | 0 | 1 |
| 1000, 10^4 | 117 | 0 | 0 | 0 | 0 |

No run at any M returned a point whose y is not optimal for the follower.

### Integer follower, BOBILib (`benchmarks/bobilib_results/bobilib_eval.json`)

The 80 smallest general-bilevel instances (by compressed MPS size) that
BOBILib reports as solved to optimality, listed in
`benchmarks/bobilib/instance_list.json`: 50 DeNegre `miblp`, 10 Xu-Wang
`bmilplib`, 11 derived from MIPLIB (`p0033`, `enigma`, `stein27`, `lseu`),
4 `T1` instances from the `zhang` set and 5 small classic instances. SCIP 10.0, 60 s per method and
instance. An objective "equals" the BOBILib optimum when it agrees to a
relative 10^-5 (BOBILib prints six decimals).

| Method | Bilevel-feasible answer | Equals BOBILib optimum | Proved optimal |
|---|---:|---:|---:|
| KKT of the follower's LP relaxation (answer checked with the follower MIP) | 65 | 16 | n/a |
| HPR-bounded leader enumeration, warm-started from the checked KKT value | 79 | 49 | 35 |

- All 35 optimality proofs agree with the BOBILib optimum, and no method
  returned an objective better than it. Proofs took a median of 2.5 s
  (maximum 39.7 s).
- The KKT model returned a checked point on 65 instances, but only 16 of
  them are optimal; it reported infeasibility on 8 instances that have a
  bilevel optimum. This is the expected behaviour of KKT applied to the LP
  relaxation of an integer follower (paper, Proposition 2).
- The enumeration stopped at the time limit on 44 instances; 14 of those
  incumbents already equal the BOBILib optimum. One instance
  (`milp_4_20_10_0110`) has an unbounded leader variable, which the
  enumeration does not handle.

## Installation

Python benchmarks (Python 3.10 or later):

```bash
python3 -m venv .venv
.venv/bin/pip install numpy highspy pyscipopt
```

Rust workspace (Rust 1.70 or later):

```bash
cd implementation
cargo build --release -p bicut-cli     # binary at target/release/bicut
cargo test --workspace                 # 718 tests
```

## Usage

Solve and check the generated LP-follower suite:

```bash
.venv/bin/python benchmarks/kkt_eval.py
```

Run the BOBILib evaluation (instances and BOBILib's reported optima are in
`benchmarks/bobilib/`):

```bash
.venv/bin/python benchmarks/bobilib_eval.py --max 80 --time-limit 60
```

Build a KKT model for your own instance from Python:

```python
from benchmarks.kkt_highs import build_kkt_highs
h = build_kkt_highs(n_x, n_y, d, e, C, D, h_vec, c, A, b, B,
                    x_lb, x_ub, x_integer=True, big_m=1000.0)
h.run()
```

Write the high-point relaxation of a TOML problem with the CLI:

```bash
bicut compile --input examples/simple_bilevel.toml --output simple.mps
bicut compile --input examples/simple_bilevel.toml --output simple.lp
```

The output format follows the file extension. The TOML format is shown in
[`examples/simple_bilevel.toml`](examples/simple_bilevel.toml): a `[leader]`
and a `[follower]` table, each with `variables`, objective coefficients and a
list of `constraints`.

## Repository layout

```
benchmarks/
  kkt_highs.py        big-M KKT model of a bilevel program with LP follower (HiGHS)
  generators.py       the four generated instance families
  kkt_eval.py         LP-follower evaluation: KKT, follower-LP check, enumeration, M sweep
  bobilib_eval.py     integer-follower evaluation on BOBILib (SCIP)
  bobilib/            BOBILib instances (.mps.gz, .aux) and reported optima
  kkt_eval_output/    results of kkt_eval.py
  bobilib_results/    results of bobilib_eval.py
implementation/       Rust workspace (types, LP formats, reformulation passes, CLI)
examples/             TOML example for the CLI
tool_paper.tex        paper
```

## Reproducing

```bash
.venv/bin/python benchmarks/kkt_eval.py                                  # about 30 min on the machine used
.venv/bin/python benchmarks/bobilib_eval.py --max 80 --time-limit 60     # at most 2 min per instance
cd implementation && cargo test --workspace
```

Solver versions used for the committed results: HiGHS 1.15.1 (highspy),
SCIP 10.0 (PySCIPOpt 6.2.1), Python 3.14, Apple M2. Timings in the result
files were taken on a shared machine and are indicative only; objective
values and status counts do not depend on timing except for runs that hit
the time limit.
